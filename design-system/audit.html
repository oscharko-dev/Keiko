Keiko · v0.3.0
Review · System Audit

The system, measured.

A full pass against an Apple-level bar — foundations, tokens, the three modes, components, states, accessibility, motion, content and governance. The verdict: a genuinely premium, accessible base that was carrying its system logic in primitives alone. This audit adds the missing semantic and component token tiers, scores every area, and names what remains as prioritised work.

01 — EXECUTIVE SUMMARY

Where Keiko stands

Strong, opinionated foundation. The risk was never taste — it was architecture and breadth: a beautiful surface with no semantic token layer beneath it, and a core component set that hasn’t yet grown to cover the full product.

Overall
4.1 / 5 · weighted

Foundations, the three modes and accessibility are already at or near the bar. Component breadth, AI-component specs and governance are the gap.

Biggest quality risk

Tokens stopped at the primitive tier

Colour, shadow and radius were tokenised, but styling reached past them to raw --fg / --card. No action.primary, no component tokens, no space / motion / z scales. Fixed in this pass.

Most important gaps

Breadth, not depth

The eight component families are excellent but partial against the required set — no table, date/time picker, slider, combobox, pagination, breadcrumbs or avatar. AI surfaces live only as patterns, not specified components.

Expected level after corrections

Apple-adjacent, durable

With the token tiers in place and the P0/P1 component work below, Keiko becomes a true central foundation — calm, precise, fully tokenised across three modes, ready to scale across teams.

03 — TOKEN ARCHITECTURE

Three tiers, one source per decision

The system now resolves every styling decision down a chain: a product component reads a component token, which resolves to a semantic token, which resolves to a mode-aware primitive. One value to change, three modes corrected at once.

TIER 1

Primitive

Raw oklch, shadows, radii. Redefine per mode.

--card
--accent
--line
TIER 2

Semantic

Intent, not appearance. Mode-agnostic names.

--surface-elevated
--action-primary
--feedback-danger
TIER 3

Component

One resolved decision per part & state.

--button-primary-surface
--input-border-focus
--ai-thinking-indicator
CONSUMED BY

Product

UI reads tier 3 (or 2). Never a raw hex.

.c-btn--primary {
  background:
  var(--button-
  primary-surface)
}
Added
Tiers 2 and 3 ship in keiko-semantic-tokens.css — additive and non-breaking: every alias resolves to an existing primitive, so the live product is byte-for-byte identical today while gaining a clean contract for tomorrow. Migration is a find-and-replace, component by component, tracked in the to-dos.
04 — IMPLEMENTED CHANGES

Done in this pass

All additive. Nothing existing was removed or visually altered; the system gained architecture it was missing.

+
Semantic token tier — background · surface · text · border · action · feedback · focus · selection · overlay · skeleton.
+
Component token tier — button, input, card, modal, popover, tooltip, toast, table, navigation, AI surfaces.
+
Spacing scale — --space-0…16, mirroring the documented 2-based rhythm.
+
Motion tokens — --dur-* durations & --ease-* curves for the documented timings.
+
Z-index scale — named layers from canvas window to tooltip; no magic numbers.
+
Opacity & blur scales — disabled, scrim, hover-veil; backdrop blur steps.
+
Type-role tokens — caption→display size ramp, weight & line-height scales.
+
Radius aliases — --radius-control / surface / floating / pill over the primitives.
+
AI / agent component tokens — response, thinking, streaming cursor, source, tool-call, confidence, permission.
+
This audit page — scorecard, architecture, changelog & prioritised to-dos, wired into the nav.

05 — OPEN TO-DOS

Scoped, ordered work to close the gap to a complete, governable system. P0 first.

Method
Priority order follows the brief: critical consistency & architecture first (P0), then breadth and standardisation (P1), then completeness and governance (P2). Every item is scoped to reuse the tokens added in this pass — no item requires a new colour, a new hue, or a one-off value.
