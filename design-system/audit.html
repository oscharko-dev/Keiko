Review · System Audit

The system, measured.

A full pass against an Apple-level bar — foundations, tokens, the three modes, components, states, accessibility, motion, content and governance. The verdict: a genuinely premium, accessible base that was carrying its system logic in primitives alone. This audit adds the missing semantic and component token tiers, scores every area, and names what remains as prioritised work.

03 — TOKEN ARCHITECTURE

Three tiers, one source per decision

The system now resolves every styling decision down a chain: a product component reads a component token, which resolves to a semantic token, which resolves to a mode-aware primitive. One value to change, three modes corrected at once.

TIER 1

Primitive

Raw oklch, shadows, radii. Redefine per mode.

--card
--accent
--line
TIER 2

Semantic

Intent, not appearance. Mode-agnostic names.

--surface-elevated
--action-primary
--feedback-danger
TIER 3

Component

One resolved decision per part & state.

--button-primary-surface
--input-border-focus
--ai-thinking-indicator
CONSUMED BY

Product

UI reads tier 3 (or 2). Never a raw hex.

.c-btn--primary {
  background:
  var(--button-
  primary-surface)
}
Done
Tiers 2 and 3 ship in keiko-semantic-tokens.css, and components.css now consumes them throughout — the find-and-replace migration is complete, with one deliberate upgrade: success moved off the interactive accent onto its own status green (--feedback-success), measured at constant lightness so the AAA contrast figures hold.

Honest line
Two things a perfect score implies are deliberately not ticked here, because ticking them would be the fake: a live visual-regression CI (per-component snapshots in all modes) and proof of adoption in packages/keiko-ui. Both are set up to be easy — the state matrix and the live contrast engine are exactly the inputs a CI would assert, and every component resolves down one token chain — but they need your pipeline and your repo to be true, so they stay open rather than claimed.
