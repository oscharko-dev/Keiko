Agent in the editor

Keiko is a coding agent, so its strongest surface lives inside the editor — not in a side chat. This page defines how agent output appears in the code: suggested, reviewable, attributable and governed. The rule throughout: the agent proposes, the developer disposes. Nothing the agent writes is committed without a human accept, and every change carries its provenance.

01 — STANCE

Proposed, never imposed

Four rules separate Keiko's in-editor agent from an autocomplete that just types for you. They are the contract the visual language enforces.

Always a proposal

Agent edits arrive as a diff you accept or reject — per hunk. Until then the file on disk is untouched.

Always attributable

Every agent-authored range can be traced to the prompt, model and policy that produced it — provenance on hover.

One accent, reserved

Agent surfaces use brand green and nothing else. If it's green in the editor, Keiko did it — green never means syntax.

Always governed

Suggestions that touch policy-controlled code are flagged before they're shown, linked to the rule that applies.

02 — INLINE COMPLETION

Ghost text

The lightest touch: a dimmed, italic continuation of what you're typing. Multi-line is allowed but indented to read as a suggestion, not committed code. Accept with Tab, dismiss with Esc — the hint is always on screen.

export function runningAgents(all) { return all.filter((a) => a.status === "running");}

Token
Ghost text is --ed-agent-ghost (= --ed-ghost): italic, dimmed, held just above the 4.5:1 legibility floor so it reads as a hint, never as live code.
Accept partial
⌘→ accepts a word at a time; Tab accepts the whole suggestion. The affordance hint lives at the editor's trailing edge, never blocking the caret.
Distinct
Ghost text must never be confused with inlay hints. Inlay = a compiler fact in a pill; ghost = a proposal in italics. Different shapes, different meanings.
03 — INLINE DIFF

Agent edits as a reviewable diff

When the agent rewrites more than a line, it doesn't silently retype — it shows the change as an inline diff with a banner and per-hunk controls. Removed lines use the diff-remove tint, added lines the diff-insert tint, and the whole range carries the accent agent marker.

04 — CHANGE REVIEW

Reviewing a multi-file agent run

For a task that spans files, accepted hunks leave a quiet agent marker in the gutter until the run is reviewed and committed. A run summary lets you step through every change, accept all, or send the lot back.

05 — INLINE PROMPT

Ask at the caret

Press the shortcut and a prompt opens exactly where you're working — scoped to the selection. The answer comes back as an inline diff (section 03), so the conversation never leaves the code.

07 — TOKENS

Agent surface tokens

Agent surfaces are governed and few. Brand green carries every one of them; red appears only where it overlaps the shared diff-remove tint.

Surface Token Role
agent range --ed-agent-line faint accent wash over agent-authored lines
agent marker --ed-agent-gutter accent left-edge + brain gutter glyph

Governance
Every agent surface here ties back to the same provenance record the System Audit and policy engine read. The editor is just the most convenient place to review it — the trust model is the product's, not the editor's.
