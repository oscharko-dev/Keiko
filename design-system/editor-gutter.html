The gutter

The narrow margin left of the code carries more signal per pixel than any other strip in the IDE: run arrows, breakpoints, version-control change bars, folding, inlay hints and blame. This page defines every column, its order, its glyph and its token — so the left edge reads instantly and never turns to noise.

01 — ANATOMY

Four columns, fixed order

The gutter is read left-to-right as action → location → change → structure. Order is fixed so muscle memory holds across files and languages.

02 — RUN & DEBUG

Runnable lines

Functions, tests and scripts that Keiko can execute show a play arrow in the icon margin. The arrow is the one place brand green enters the gutter — running code is the product.

Glyph
The arrow is the Lift run glyph in --ed-run-glyph (= --accent-text). On a passing run it stays green; a failed last-run tints it --ed-error.
Click
Click the arrow → the run popup (left): Run, Debug, Coverage. The same actions Keiko exposes in the toolbar and command palette — one vocabulary, three entry points.
Restraint
Only directly runnable declarations get an arrow. Nesting every callable would turn the margin into a forest — we mark entry points, not every function.
03 — BREAKPOINTS

Breakpoint states

Breakpoints differ by shape as well as colour, so they survive the high-contrast and colour-blind paths: a filled disc for a line stop, a notched disc for conditional, a square for a logpoint, a hollow ring when unverified.

04 — VERSION CONTROL

Change bars

A 3 px bar between line number and code shows the uncommitted state of every line against HEAD. Hovering a bar opens the inline change popup — diff the hunk, roll it back, or stage it, without leaving the line.

20 const v2 = "/api/v2";
21 const url = v2 + path;
22 return fetch(url);
23 // staged
State Token Mark
added --ed-vcs-added bar (diff green)
modified --ed-vcs-modified bar (info)
removed --ed-vcs-removed caret (danger)
staged --ed-vcs-staged bar (accent)
Reuse
Added reuses the diff-insert green; removed reuses --danger. The gutter and the diff surface speak one colour language.
05 — CODE FOLDING

Folding & placeholders

Fold controls stay hidden until you hover the gutter — structure on demand, not permanent clutter. A collapsed range leaves a quiet inline placeholder so nothing feels lost.

2 id: string;

4}

Line 1 is an expanded block (down chevron); line 6 is collapsed (right chevron) with the { … } placeholder in --ed-fold-placeholder. Hovering a folded placeholder previews its content in a popup.

06 — INLAY HINTS

Inlay & inline values

Compiler-derived facts shown in the code without editing it: parameter names at call sites, inferred types, and — while debugging — live values at the end of the line. Hints read as chips, clearly distinct from real tokens.

8const items: Agent[] = load();
9slice(start: 0, end: 5);
10 return items.length;items = 12
Inlay
Type + parameter hints use --ed-inlay-fg on a faint --ed-inlay-bg pill — present but never mistaken for code you can edit.
Inline value
Debug values sit at the line end in the info hue (--ed-inlay-value-*), matching the debugger's variable colour so the eye links them.
Inline completion
AI ghost-text is a related but distinct surface — italic, dimmed, accepted with Tab. It lives in Agent in Editor.
07 — ANNOTATIONS

Blame annotations

An optional left-of-gutter column attributes every line to its last commit — author and relative date. Quietest text on the surface; the line under the cursor lifts so you can read who last touched it.
