Markdown views

Markdown is half the files in an agent repo — prompts, specs, AGENTS.md, docs. So a .md file opens with a three-way view switch: Code (raw source), Split (source beside a live preview), and Preview (the rendered document). One toggle, top-right, that remembers your choice per file.

01 — THE VIEW SWITCH

One file, three views

The switch lives at the trailing edge of the editor toolbar — three segments, the active one accent-marked. Click through them: the file below is live.

02 — CODE VIEW

Markdown as source

The raw view is a normal code surface with a Markdown grammar: structural marks stay visible and quietly coloured so you edit the document and see its shape. It reuses the syntax palette — no new hues.

03 — SPLIT VIEW

Source beside preview

The working view for writing: edit on the left, watch it render on the right. Scrolling is synced by source position, and a thin divider — the same accent group-edge as a code split — marks the seam.

Task-list checkboxes render as real, tickable controls (the one accent moment in the preview). GitHub-flavoured extras — tables, task lists, fenced code — all render; the source stays the source of truth.

04 — PREVIEW VIEW

The rendered document

Reading mode: the source disappears and the document reads like a doc. This is the same renderer used everywhere Keiko shows Markdown — chat answers, run summaries, PR bodies — so a prompt looks identical wherever it surfaces.

06 — PRINCIPLE

Source is truth, preview is a lens

Three views, one fileCode, Split and Preview are lenses on the same buffer — never separate documents. Edits in Split's source pane are the edits; the preview is read-only output.
Choice persistsThe view mode is remembered per file (and per file-type default), so the editor opens the way you last read that document.
No new coloursCode view reuses the syntax palette; Preview reuses the UI ramp + one accent. Markdown adds structure, not a new spectrum.
One renderer everywhereThe preview renderer is shared with chat, run summaries and PR bodies — a prompt looks the same in the editor as it does when the agent quotes it back.
