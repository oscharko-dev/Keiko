Tool windows

Everything that frames the code well: the icon stripes that summon panels, the project tree, and the docked tools — Run, Problems, Terminal and Git. Tool windows are shell, not code: they live on --surface, defer to the editor, and share one header grammar.

02 — STRIPES

Tool-window stripes

The narrow rails on the window edges are the index to every panel. An icon's position encodes its dock side; its state encodes whether the panel is open and whether it wants attention.

Open
An open panel's button is accent-washed with a 2 px edge marker (left rail marks left; right rail marks right). One glance tells you the current layout.
Attention
A panel with new content (failed run, fresh notification) shows a danger dot — the only thing on the stripe allowed to be loud.
Right rail
The right stripe is Keiko's home: notifications, the agent (brain), and data sources — assistants dock opposite the project structure.
03 — PROJECT TREE

File tree & states

06 — PRINCIPLE

Shell defers to code

One header grammar Every docked tool has the same head: a micro-caps title, a trailing action cluster, optional counts. Run, Problems, Terminal and Git are visibly one family.
Surface, not well Tool windows sit on --surface; only consoles (Run/Terminal) borrow --ed-bg because they are code output.
Colour = VCS or severity In the tree a name's colour means version-control state; in Problems an icon's colour means severity. Colour is never decorative in a panel.
Stripe = the index The stripes are the single source of truth for “what's open”. Opening a panel is reversible from one click; nothing hides state.
