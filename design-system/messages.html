Messages & feedback

How Keiko tells you something went wrong, needs care, or simply happened. Four severities, each with its own icon shape — never colour alone — wrapped in the calm, precise voice from the content guide. Inline messages, banners, toasts and field errors all share one severity system. Toggle the theme; every level holds its contrast in both.

01 — SEVERITY

Four levels

Pick by consequence, not by drama. The icon shape carries the meaning so the message still works in greyscale, for colour-blind users, and under glare.

LevelTokenMeansWhen
Error--dangerSomething failed or is blocked.An action couldn't complete; data is at risk. Needs a fix or a decision.
Warning--warnProceed with care.Allowed, but with a consequence — a limit near, an irreversible step ahead.
Info--infoWorth knowing, nothing required.Context, scope, a tip, a neutral state change.
Success--accent-textIt worked.Confirm a completed action — quietly. Routine success often needs no message at all.
Shape, not colour
Error is an X-in-circle, warning a triangle, info an i-in-circle, success a check. Each is a Lift glyph with the one-seam signature, so severity reads without relying on red/amber/green alone — satisfying WCAG 1.4.1.
02 — INLINE MESSAGES

Inline messages

The workhorse: an icon, a title, one calm line, and at most two actions. Sits in context — in a panel, under a section, inside a window. .c-msg--danger / --warn / --info / --ok.

Couldn't connect to release/0.2.0
The branch is private or the token expired. Reconnect to continue grounding answers in this source.
Approaching the per-chat source limit
7 of 8 sources connected. Connecting more will drop the oldest from this chat's grounding.
Answers are grounded in src/
This window reads from the connected folder. Replies cite the files they came from.
Workspace updated
Coder applied the design tweaks across 4 windows.

.c-msg + .c-msg-ico / -tt / -tx / -act / -close · title is --fg, body --fg-muted; only the icon & border carry the severity tone.

03 — BANNERS

Banners

System-level state that affects the whole surface, pinned to the top of a window. Full-width, one line, dismissible only if non-blocking. .c-banner--*.

Connection lost — answers may be out of date.
Read-only — you don't have write access to this workspace.

.c-banner attaches under the window header; blocking banners (error) keep a primary action and no dismiss.

04 — TOASTS

Toasts

Transient confirmation for a thing that just happened and needs no decision. Auto-dismiss (≈ 5s), bottom of the surface, one at a time. Never use a toast for an error the user must act on — that's an inline message or banner.

Connected to release/0.2.0Grounding is live for this chat.
Window minimized to the dockFiles · reachable in one click.
Couldn't save settingsRetrying automatically…

.c-toast--ok / --info / --warn / --danger — the chip tints to the severity; copy stays calm.

05 — FORM VALIDATION

Inline field errors

Validate on blur or submit, never on every keystroke. The error sits under the field it belongs to, tied with aria-describedby, and the field border turns danger. Keep a neutral hint in the same slot when valid.

Use letters, numbers and dashes only.
Absolute path to a folder, repo or file.

.c-field--invalid + .c-field-error · .c-field-hint for the resting helper. Error text is --danger (AA) and always carries the error glyph.

06 — VOICE

Write the message

Same rules as the content guide, sharpened for trouble: say what happened, why, and the way out — in that order. Calm even in failure. No blame, no exclamation marks, no “Oops”.

Do
Couldn't connect to release/0.2.0. The token expired — reconnect to continue.
Fact, cause, way out. The user knows exactly what to do.
7 of 8 sources connected. One more drops the oldest.
States the consequence plainly, before it happens.
Retrying automatically…
Tells the user the system is handling it; no action demanded.
Don't
Oops! Connection failed 😬
Cute, vague, no cause and no next step — and emoji aren't the brand.
Error 500: ECONNREFUSED at socket.js:44
Raw, blaming, unreadable. Log the trace; tell the human the outcome.
You entered an invalid name!!!
Accusatory and shouty. Describe the rule, not the user's mistake.
07 — ACCESSIBILITY

So everyone gets the message

Live regionsBlocking errors use role="alert" (assertive); info & success use role="status" / aria-live="polite" so a screen reader announces them without stealing focus.
Shape + textSeverity is icon + word + tone — never colour alone (1.4.1). Each level owns a distinct glyph.
Field errorsaria-invalid="true" on the input, error text linked via aria-describedby; focus moves to the first invalid field on submit.
ContrastIcon & border tones clear 3:1 in both themes; success uses --accent-text so green holds up on white. Body text is --fg-muted (AA+).
DismissEvery close control has an aria-label and a ≥ 24px target; dismissing is never the only way to act on a blocking error.
PersistenceErrors that need action don't auto-dismiss. Only confirmations time out.
