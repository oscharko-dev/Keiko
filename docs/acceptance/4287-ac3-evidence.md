## Independence and limits

The reconciliation fixture at
[jira-report-reconciliation.fixture.ts:4](../../packages/keiko-connectors/src/jira-report-reconciliation.fixture.ts#L4)
interprets a closed subset of JQL directly against synthetic Jira facts. It imports neither the report
aggregator nor the production JQL parser. Unsupported clauses throw; they cannot silently select the
whole project. Each reconciliation is a separate HTTP-port request with `maxResults=0` and an empty
issue page, using Jira's returned `total`. Positive nonzero groups, one estimated zero, one uncovered
requirement and an absent issue type distinguish measured zero from unavailable evidence.

Estimate sums are independently reconciled by JQL counts for each fixture estimate value, rather than
by calling or copying the production issue aggregation. The JQL buckets use explicit minute units (`15m` for 900 seconds), following the
[Data Center duration field reference](https://confluence.atlassian.com/jirasoftwareserver101/advanced-searching-fields-reference-1455427012.html#Advancedsearchingfieldsreference-Originalestimate).
Native Jira JQL has no sum aggregate here.
The requirement queries cover exact synthetic identifiers; the fixture is not a general Jira search
engine. The orphan/empty-epic reconciliation uses a deliberately explicit hierarchy with no bug links;
existing graph tests cover linked issues, inferred parents and changing hierarchy evidence.

No metric mismatch was found in these scopes. The new evidence tests pass against the assigned base;
there is no product fix or failing-first regression claim for AC3. These proofs do not establish metrics
for every Jira installation, permissions configuration or concurrently changing real project.
