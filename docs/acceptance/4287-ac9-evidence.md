## Pending approval lifetime and explicit Stop

The browser run exposed a false claim: reloading a pending approval revoked it. The original
request-close cancellation reached the tool wait and changed the saved approval to `revoked`.
Component serialization alone did not prove this lifetime. The original browser run recorded
`5 failed | 20 passed`; four failures reached revoked approvals, while the fifth was a test
measurement mismatch between `innerText` and `textContent`. Reload comparisons now use exact
`innerText` before and after, with no whitespace normalization.

The product fix keeps the original admitted worker only for an opted-in canonical text-Chat request whose exact pending
review was observed by the original live app session. Observation grants no action and renews no
expiry. The original authority, binding, action digest and one-use approval remain authoritative.
Transport detachment stops SSE delivery; it does not resend a model turn or a native operation.
Explicit Stop cancels the exact canonical turn through an authenticated endpoint. Unleased
requests preserve their existing disconnect cancellation. Server restart recovery is outside this
page-reload claim.

## Transport and Stop ownership closeout

The integrated Knowledge-Pod case uses `/api/chats/messages/grounded`, not the ordinary Chat
stream. Its initially revoked approval exposed the missing lifetime path. The same bounded
continuation now covers ordinary streaming, native buffered fallback, direct grounded Chat and
mixed buffered grounding. The production-handler proofs are
[jiraChatToolTurn.test.ts:2446](../../packages/keiko-server/src/atlassian/jiraChatToolTurn.test.ts#L2446)
and [grounded-jira-mixed.public-handler.test.ts:3039](../../packages/keiko-server/src/grounded-jira-mixed.public-handler.test.ts#L3039).
Header-absent requests retain their existing disconnect cancellation. Canonical Voice explicitly
opts out on both buffered and grounded routes so barge-in keeps its immediate cancellation
semantics ([useChatSession.test.tsx:4301](../../packages/keiko-ui/src/app/components/desktop/hooks/useChatSession.test.tsx#L4301)).

A fresh independent audit found delayed and duplicate Stop responses could overwrite a newer turn
when a restored turn had no local controller. Three failing-first cases exposed the null-controller
ABA and duplicate POSTs; the fix uses opaque attempt ownership, invalidates it on new admission,
and coalesces an in-flight exact-target Stop. Eleven targeted cases then passed. Only the owning
attempt may publish its error, confirmation or status; original server-side approval/effect guards
remain authoritative. The opaque owner is at
[useChatSession.ts:4952](../../packages/keiko-ui/src/app/components/desktop/hooks/useChatSession.ts#L4952),
with regressions at [useChatSession.test.tsx:1910](../../packages/keiko-ui/src/app/components/desktop/hooks/useChatSession.test.tsx#L1910)
and [:1975](../../packages/keiko-ui/src/app/components/desktop/hooks/useChatSession.test.tsx#L1975).

The draft browser test now compares both canonical collapsed text and re-expanded full text, plus
the entire persisted tool transcript and canonical turn identity. Local expansion and unsubmitted
checkbox choices are not stored in the Chat record. Submitted exclusions remain part of the exact
server-recorded approval. These proofs cover canonical proposal, approval, receipt and batch data;
they do not promise persistence of unsubmitted local view choices.

## Limits and claim-table update for the integrator

- Axe/jsdom and automated Chromium journeys do not establish native screen-reader
  qualification or subjective visual readability. Existing EN/DE browser accessibility
  journeys include keyboard and visual-mode checks; they use synthetic transports.
- The matrix covers the requested card families and inventories the existing specialized
  tests. It does not assert that one matrix test exercises every one of the 439 operations.
- For the protected `4287-jira-claim-evidence.md`, update the EN/DE/UI row to cite this AC9
  matrix and disclose that raw built-in approval labels and pending-review lifetime required product fixes. Keep the
  explicit qualification that unknown custom IDs and Jira issue keys remain exact identity.

The protected ADR-0128 also needs the integrator's description of the bounded, same-session
page-reload continuation and exact explicit Stop. Neither the ADR nor the protected claim table
was edited here.
