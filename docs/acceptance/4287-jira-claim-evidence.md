## Customer wording and false claims

- The exact catalog count is **439 native Jira Data Center operations, 216 reads and 223 writes**.
  The three local compositions (`jira.report`, `jira.draft-stage`, `jira.draft`) and two discovery
  tools are separate. Five native reads use POST; HTTP-verb counting is incorrect.
- In **Ask for approval**, the human reviews the exact credential-safe proposed action before
  dispatch. This proves the proposed arguments; governed trace footer/labels and Jira-format
  serialization can change the final native representation after preview. A literal byte-exact
  final-payload claim remains unproven. **Supervised workspace** also requires Jira write approval; **Full access** may proceed
  inside current bounded authority. Mode selection does not grant Jira permissions or admin scope.
- A batch is a governed Chat draft with per-item durable writes, dependency ordering and
  reconciliation. It is **not atomic**, and resume is an explicit later execution, not an
  unattended background retry. A crash or timeout with uncertain effect remains pending/unknown.
- **False capability claim:** attachment downloads into an approved workspace do not exist. The
  implemented attachment reads are metadata only. The new negative proof demonstrates refusal;
  it cannot establish a successful contained download. Do not publish that feature claim. Adding
  downloads requires a governed implementation; none is silently introduced by this evidence
  branch. The user was asked whether to retain the unsupported verdict or expand the feature.
- “The same complete Jira tool inventory exists in Chat and Coding” is also false. Both have Jira
  tools, but Coding omits Chat-owned `jira.attach` and `jira.draft` by design. Existing tests pin
  those authority boundaries; removing them to satisfy marketing wording would be unsafe.
- The PAT is encrypted in the secret vault. On the keychain path, the OS keychain holds its
  encryption key, not a plaintext PAT in config. The supported env/keyfile fallbacks mean
  “always stored directly in an OS keychain on every platform” would be false.

The cause-level runtime repair is the request-owned credential reflection floor, including its
registered body-free suppression evidence and bounded, cancellable scanning. The PAT fix was proven red against the actual
arbitrary resolved PAT, rather than relying on a known token shape; the original shape-only test
was insufficient. Missing downloads remain an outstanding capability, and the final-payload
preview remains unproven. Neither gap is represented as completed implementation.
