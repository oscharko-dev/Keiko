surfaces while preserving Keiko's deterministic-first and existing BFF authority boundaries.

## Security boundary review

- Permission requests remain presentation and lifecycle controls for existing queued actions. They do
  not create a new route, permission token, terminal/browser/file authority, or model capability.
- Sensitive chat memory forget remains behind the existing memory governance route and destructive
  acknowledgement contract. The UI adds a typed confirmation before it can call that route.
- Regenerate accepts only `chatId`, `projectPath`, `assistantMessageId`, optional `modelId`, and
  optional memory settings. The handler validates the project path, chat ownership, model selection,
  latest-turn status, assistant role, and ungrounded state before calling the Model Gateway.
- Grounded chat answers are deliberately not regenerated by the plain chat route, so citations and
  grounded evidence are not silently discarded.
- The store update primitive rewrites only assistant rows and preserves the message id. User/system
  turns cannot be rewritten through the regenerate path.
- Cancellation uses the HTTP disconnect/AbortController boundary and returns a cancelled response
  without persisting a replacement assistant message.
