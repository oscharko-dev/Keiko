# Epic 2088 Foundation-wave production audit

Audit date: 2026-07-16. Audited baseline: `origin/dev` at
`1056821a5b861f076cc88e120492aaf5cad37b9d`. Scope: Epic #2088 Foundation wave and child epics
#2089 through #2096 (M1 through M8).

This record distinguishes implementation defects from later-wave work and from behavior that the
governing ADRs intentionally exclude. It is a source-level and composed-product audit, not a claim
that closing the Foundation wave closes the parent program: #2088 retains later milestones M9
through M16.

## Binding invariants

- Repository reads and writes initiated by an editor agent remain inside a valid, current Authority
  Envelope. Workspace switches require fresh authority; read-only operations are not exempt.
- Managed language servers are default-off, explicitly activated per workspace, provisioned by an
  operator, capability-negotiated, and fail closed before process dispatch.
- Editor, server, and UI wire envelopes have one owner in `keiko-contracts`; malformed or drifted
  successful HTTP bodies are not trusted.
- Conflict, file-watch, diagnostics, debug, and model-retention state is versioned and scoped to the
  canonical workspace/document identity. Time or path coincidence is not accepted as provenance.
- Evidence contains bounded, redacted projections. Raw workspace content, diagnostics, endpoints,
  and debug output do not enter audit or release manifests.
- Performance evidence is Linux-authoritative, non-vacuous, reproducible from raw samples, bound to
  the measured source tree, and compared against the pinned D12 baseline in alternating order.

## Deliberate exclusions reconciled against the live issues

- Issue #2116 explicitly excludes production activation of `DryRunToolPort` / `run-engine` from the
  M3 slice. No parallel production editor-agent tool host was added.
- ADR-0136 deliberately excludes an agent debug-control/read surface from M8. Debugging remains a
  local-human-controlled, server-owned DAP surface; the older parent-epic wording is reconciled to
  the ADR rather than implemented as an authority expansion.
- The parent Epic #2088 remains open after Foundation closure because M9 through M16 are outside
  this delivery slice.

## Verification policy

The candidate is accepted only after the complete local-first `npm run codex:pre-pr` report is
green, all touched-area gates are green, Linux-authoritative D12/bundle evidence is regenerated,
the debug-launch mutation gate reports no surviving or uncovered mutants, and the exact pushed PR
head passes every direct app-bound required check. No gate, coverage floor, evidence bound, policy,
or branch protection setting may be weakened to obtain that result.
