# Epic 2285 M11 multi-root, trust, profiles, and local-history demo

This is the clean-checkout demonstration for Issue #2533 and Epic #2285. It proves the composed
M11 product path without adding a second workspace, trust, settings, or history subsystem. The
browser journey uses the real Keiko UI and BFF routes; it does not intercept or replace product
requests.

## Prerequisites

- Git and npm from a clean checkout.
- Node.js 24.18.0 and the npm version pinned by the root package metadata.
- Chromium installed through the repository Playwright dependency.
- No provider binary, external service, customer workspace, credential, or network fixture.

## Clean-checkout reproduction

```bash
git clone https://github.com/oscharko-dev/Keiko.git keiko-m11-closeout
cd keiko-m11-closeout
git fetch origin feat/epic-built-in-editor-2285-M11
git checkout --detach origin/feat/epic-built-in-editor-2285-M11
npm ci --ignore-scripts
npx playwright install chromium
npm run test:editor-m11-closeout
npm run check:editor-m11-performance
npm run test:e2e:editor-m11-closeout-2533
```

`test:editor-m11-closeout` is deliberately issue-scoped. It executes the M11 adversarial,
migration, redaction, accessibility, and composed-state evidence files named by #2533. It is not a
replacement for the repository green bar or an invitation to use CI as a local test loop.

## Automated product journey

The Playwright proof creates two disposable local roots and drives this sequence:

1. Register both roots through the real project route, add the second root through the current
   manifest-bound mutation route, and create the named editor profile through the real
   `PATCH /api/editor/settings/profiles` route. These three steps run before the browser opens, so
   the journey demonstrates the profile **switch** through Settings, not the create — creation
   through the Settings control is covered by `EditorProfilesPanel.test.tsx` and by the manual
   walkthrough below.
2. Open the real multi-root editor and Explorer.
3. Explicitly trust root Alpha through the confirmation prompt.
4. Switch to root Beta, choose the safe prompt action, and verify that Alpha remains trusted while
   Beta remains in Restricted Mode.
5. Return to Alpha, then switch to the named profile through the Settings Editor tab and confirm the
   active profile changed.
6. Save two file versions, open local history, restore the oldest version through the authenticated
   app-session channel, and prove that no browser storage sink — cookies, `localStorage`,
   `sessionStorage`, or IndexedDB — receives checkpoint content.
7. Run real-browser axe checks over the multi-root Explorer, the Settings Editor tab with its
   profile controls on screen, and the history panel; retain the exact Explorer finding tracked by
   #2605, then retain a composed PNG and content-free timing attachment. Settings and history have
   no serious/critical violations; the Explorer rule is not disabled or excluded.

The browser spec is
[`editor-m11-closeout-2533.spec.ts`](../../tests/e2e/editor-m11-closeout-2533.spec.ts). Its static
guard proves that the journey contains no `page.route` interception and retains the trust, profile,
history, app-session, axe, and visual assertions. It also pins the two things a refactor undoes
silently: that the settings axe scan is preceded by opening the Editor tab (a replaced page mounts
the settings window on Models again), and that the storage probe still reads IndexedDB and
`sessionStorage` rather than narrowing back to `localStorage`.

## Manual product walkthrough

For an operator walkthrough, start Keiko with `npm run dev:start` and use disposable local roots:

1. Add two roots to one editor workspace and confirm that Explorer and editor tabs preserve their
   independent root identities.
2. Trust only the first root. Confirm the second root shows Restricted Mode and does not advertise
   execution or agent authority.
3. Open Settings → Editor, create a named profile, switch to it, and confirm the active profile is
   visible without changing either root's trust state.
4. Save several versions of a file in the trusted root, open File history, compare and restore an
   older checkpoint, and confirm the pre-restore state becomes a new checkpoint.
5. Revoke the trusted root and confirm the same UI returns to Restricted Mode.
6. Stop Keiko with `npm run dev:stop`.

## Capability delta against #2088

| #2088 foundation-wave baseline                                     | M11 capability proven here                                                                                                            | Deliberate boundary                                                                            |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| One active editor root selected workspace context.                 | One ordered manifest holds up to 32 explicit roots; Explorer, search, editor sessions, and effectful dispatch preserve root identity. | Focus never supplies missing authority, and M11 has no cross-root atomic mutation transaction. |
| Package-script trust was a single-root consumer control.           | Canonical per-root Workspace Trust drives Restricted Mode across scripts, language servers, and editor agents.                        | Opening, focusing, or profiling a root never grants trust.                                     |
| M7 settings resolved built-in, user, workspace, and policy layers. | M11 adds profile and per-root layers through the same settings control plane.                                                         | Profiles cannot carry roots, trust, credentials, runtime identities, or delivery authority.    |
| Hot exit retained the latest encrypted recovery snapshot.          | Local history retains a bounded encrypted checkpoint chain with compare, pin, and governed restore.                                   | It is not Git history, memory, chat, or a Code-task transcript store.                          |
| Editor-agent context was bound to one current workspace.           | Agent sessions/actions carry exact manifest and root bindings and reject stale, forged, or cross-root reuse.                          | Multi-root context is decomposed per authorized root; it is never blended implicitly.          |

This delta closes an identified #2088 roadmap gap. It does not claim full VS Code replacement or
remote-workspace parity. Remote settings sync, remote workspaces, arbitrary extensions, and
cross-root atomic effects remain outside M11.

## Evidence artifacts

Successful Playwright output contains:

- `editor-m11-closeout.png` — the composed multi-root/profile/history state;
- `editor-m11-closeout-metrics.json` — content-free profile-switch and restore durations; and
- the Playwright trace/screenshot-on-failure policy inherited from the shared editor configuration.

Artifact retention is CI-owned. Raw traces are not governance evidence because they can include
fixture content; only the bounded attachments and redacted summaries are cited by closeout.
