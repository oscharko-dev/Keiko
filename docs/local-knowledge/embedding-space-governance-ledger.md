## Post-merge audit hardening

P0 audit branch `codex/audit-knowledge-pods-p0` reviewed the merged Knowledge Pods P0 state on
2026-07-05 and found two evidence-backed hardening gaps:

- Chat Knowledge Pod selection did not surface embedding mismatch, unavailable-model, opaque, or
  reindex guidance even though the Local Knowledge graph already did. The picker now shows the same
  redacted guidance in the selected state and in the option list without exposing provider
  endpoints, private paths, raw source text, or raw query text.
- Server-generated no-evidence and selected-scope conflict messages still used legacy
  connector/capsule product language in user-visible paths. They now use Knowledge Pod and
  Knowledge Pod Set terminology while keeping internal `KnowledgeCapsule` and `CapsuleSet`
  contracts unchanged.

GitHub state observed during the original delivery audit:

- At delivery time #1818 and child issues #1843-#1848 were open with
  `status: ready for human review`; no issue, project, PR, or board status was changed by the
  audit because the human-control invariant leaves closure and merge actions to an explicit
  maintainer step.

Post-merge update (2026-07-06): the delivery was subsequently merged to `dev` by an explicit
maintainer step, and #1818 plus child issues #1843-#1848 are now closed with `status: done`. This
ledger row is corrected here to remove the stale "remain open" claim; the closure remained a human
action, consistent with the invariant above.

## Known limits

- Remote and federated pods remain opaque future work unless they provide a reviewed
  compatibility contract.
- This change does not install, download, or mandate any embedding provider.
- This change does not automatically reindex private content.
- Linux CI remains authoritative for platform-specific release evidence.
