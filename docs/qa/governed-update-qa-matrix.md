## Synthetic older-version fixtures

No new permanent fixture directory is required for #1698 because the older-version cases are already
covered by focused tests-as-code:

- `update-preflight.test.ts` uses synthetic `0.2.9`, `0.2.10`, `0.2.11`, and `0.2.12-beta.1`
  metadata to prove numeric semver comparison, cumulative notes, fallback behavior, supported-from
  blocking, and prerelease exclusion.
- `release-impact-governance.test.mjs` uses a synthetic previously published `0.2.10` catalog entry
  and a current `0.2.11` root manifest to prove append-only history, missing-entry failure,
  duplicate-note failure, invalid baseline coverage, and publish-gate completeness.
- The source catalog records `supportedFrom: ["0.2.0"]` for the reviewed `0.2.11` entries, keeping
  the public 0.2.0 baseline explicit for forward compatibility.

## Security, accessibility, and UX settlement

Security settlement:

- Public metadata requests remain anonymous and server-side; browser UI calls only the local BFF
  helper routes.
- State-changing update routes use CSRF validation, request validation, no-store behavior, and
  route-level error mapping.
- Package mutation runs through a dedicated updater authority with fixed argv, no shell strings, a
  bounded command policy, one active session, and a durable lock.
- Unsupported install modes, ambiguous launch roots, policy-disabled mutation, missing reviewed
  metadata, and manual-review remediation fail closed before mutation.
- Recovery snapshots and audit events are content-free local runtime artifacts and exclude customer
  repository files, secrets, raw logs, prompts, model output, package-manager output, and private
  paths.

Accessibility and design-system settlement:

- Component tests include jest-axe coverage for the normal update window and explicit assertions for
  focus, collapsed disclosures, critical/manual/remediation text, affected-feature labels, native
  progress, and startup alert/status behavior.
- The Playwright evidence suite opens the real packaged UI from Settings/startup entry points,
  captures dark, light, high-contrast, prefers-contrast, forced-colors, reduced-motion, startup,
  settings, responsive manual, and progress states, and writes
  `update-experience-fidelity-proof.json`, `a11y-proof.json`, and `manifest.json`.
- Product-copy review confirms no auto-update framing, no color-only critical/manual warnings, no
  unsupported-install error framing, and no exposed technical logs in primary copy.

UX settlement:

- The main path is explicit review before install: current version, target version, patch notes,
  state impact, policy/install-mode status, and remediation requirements are shown before mutation.
- No-update, blocked/manual, progress, restart-required, failed, succeeded, and remediation states
  have distinct copy and action affordances.
- The update surface is intentionally available from Settings and startup notification only; it is
  not exposed as a generic command-palette action or arbitrary command runner.

## Out of scope and known limitations

The final #1698 evidence intentionally leaves the following outside this epic:

- Prerelease, beta, canary, or enterprise-private update channels.
- Offline package import or private package-cache update flows.
- Native installer, Electron/Tauri updater, or OS-level update service.
- Package downgrade rollback.
- Broad enterprise policy administration beyond the local updater policy gate.
- Snapshotting, rewriting, migrating, or repairing customer repository files.
- A new permanent GitHub screenshot-upload workflow.

No unsafe update path was found in the covered matrix. Future release work still needs maintainer
review for publish-time `approvalReference` values and the final `epic/governed-updates` -> `dev`
human-gated PR, because local issue evidence is not a substitute for protected-branch review.
