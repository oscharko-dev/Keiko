# OpenCode capability parity matrix

Status: working inventory for [#3874](https://github.com/oscharko-dev/Keiko/issues/3874) and epic
[#3897](https://github.com/oscharko-dev/Keiko/issues/3897), refreshed 2026-10-23 against the
working tree of PR oscharko-dev/Keiko#4064. Pinned runtime: OpenCode 2.1.4 (`OPENCODE_PINNED_VERSION`,
commit `68bc26b7`, [versions][versions]); 2.0.10 stays admissible only until npm runtime packages
built from 2.1.4 are published. Executed heads and pending qualification are recorded separately in
the live lab ledger ([lab][lab]). This document does not qualify an unexecuted current head, and no
row records a run of the opt-in real-binary suites on the current head, except the five rows of
[section 3.5](#35-real-binary-qualification-of-2026-10-24).

## Purpose

Issue #3874 asks for a matrix of what OpenCode can do against what the Coding Workbench offers.
Owner direction of 2026-10-23 ([ADR-0137][adr-0137] D10): the Workbench offers the original OpenCode
service as it runs standalone, and Keiko is the foundation around it (Git delivery, the Model
Gateway, later MCP, the UI). The only functions that may be unavailable are the ones that depend on
outbound internet or on other servers at a firewalled customer. Every other standalone function that
is narrower, switched off or missing here is an open acceptance item. A slow Model Gateway response
is absorbed by Keiko's gateway (S10), not by shortening the runtime's patience.

Two tool profiles exist, selected only by the server (`productionOpenCodeToolProfile`,
[deps][deps]):

- **Native profile (macOS).** The original OpenCode tools, agents and configuration run in the
  pinned service. Keiko binds the autonomy mode, the live Authority Envelope and the hard denials
  through the supported permission hook and the kernel (Seatbelt) boundary.
- **Mapped profile (`direct`; Linux and Windows).** OpenCode's native workspace tools are denied and
  the model sees 18 tools: native `question` plus 17 governed `keiko_*` tools. It stays in force
  where no native boundary is qualified. The `code-mode` mapped profile exists only for tests and an
  explicit server selection.

Statuses in section 3 describe the **native profile on macOS**. Notes marked "Mapped" state what the
mapped profile offers on Linux and Windows; those statements are carried over from the 2026-10-08
revision and were not re-verified in this refresh. The three autonomy modes, the Authority Envelope and the
mode-independent hard denials remain Keiko-owned ([ADR-0124][adr-0124], [ADR-0125][adr-0125],
[ADR-0129][adr-0129], [ADR-0138][adr-0138]); native permissions cannot widen them. Chat repository
search and its recursive search subsystem are retained unchanged.

Earlier revisions of this document tracked inactive private seam controls (a guarded Read helper,
instruction discovery fixtures, an inactive native host) as prerequisites of native Read. The native
profile supersedes that route: the original tools run in the service under the permission hook and
the kernel boundary, so those paragraphs were removed. The matrix grants no authority and adds no
behaviour. It refreshes, for 2.1.4, the comparison in
[coding-workbench-audit-3560.md][audit-3560]; the older
[opencode-native-quality-audit.md][audit-1517] remains the record for 1.17.17.

### Mode summary used in the notes

Abbreviations: Ask = Ask for approval (`governed-assist`), Supervised = Supervised workspace
(`supervised-coding`), Full = Full access (`autonomous-delivery`). The shared policy is the total,
monotonic matrix of [ADR-0138][adr-0138] D2:

| Mode       | Workspace-contained, low or medium risk | Workspace-contained, high or critical risk | Internet          | Delivery                                                                                                                                              |
| ---------- | --------------------------------------- | ------------------------------------------ | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ask        | approval-required                       | approval-required                          | approval-required | approval-required                                                                                                                                     |
| Supervised | allowed                                 | approval-required                          | approval-required | approval-required                                                                                                                                     |
| Full       | allowed                                 | allowed                                    | allowed           | approval-required; Code-task commit, push and draft-PR execute are authorized by the live envelope (ADR-0138 D3 item 5); merge is never model-visible |

Reads and planning are allowed in every mode (ADR-0124 D1). Two reminders apply to every row. A
matrix cell is a ceiling, not a capability: it applies only where an execution path exists
(ADR-0138 D2, availability clarification). The hard denials hold in every mode (ADR-0129 D3):
invalid or expired authority, workspace escape, denied sensitive paths, secret exfiltration,
unsupported actions, exhausted budgets and platform restrictions.

### How the native policy maps actions onto that matrix

`decideOpenCodeNativePolicy` ([native-policy][native-policy]) classifies each permission the runtime
evaluates. [native-policy-test][native-policy-test] pins these classifications; `skill`, `question`,
`list` and `doom_loop` share the read set without an assertion of their own.

| Native permission                                                                                                                | Classification                     | Ask     | Supervised | Full    |
| -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | ------- | ---------- | ------- |
| `read`, `list`, `glob` and `grep` (the searched directory is checked), `skill`, `subagent`, `question`, `todowrite`, `doom_loop` | workspace read                     | allowed | allowed    | allowed |
| `edit` (the `edit`, `write` and `patch` tools)                                                                                   | workspace-contained, medium        | asks    | allowed    | allowed |
| `shell`, vetted (package scripts, tests, type checks, linters, builds, read-only Git and file inspection)                        | workspace-contained, low           | asks    | allowed    | allowed |
| `shell`, any other command                                                                                                       | workspace-contained, high          | asks    | asks       | allowed |
| `webfetch`, `websearch`                                                                                                          | internet                           | refused | refused    | allowed |
| plan-directory read or edit (the plan agent's notes)                                                                             | planning                           | allowed | allowed    | allowed |
| `external_directory` outside the plan directory, a path outside the workspace                                                    | hard denial (`workspace-escape`)   | refused | refused    | refused |
| `.env`, keys and other credential-named paths                                                                                    | hard denial (`sensitive-path`)     | refused | refused    | refused |
| Git delivery or `gh pr`, `repo`, `release`, `api` through the shell                                                              | hard denial (`delivery-reserved`)  | refused | refused    | refused |
| Code Mode `opencode_session_move`, `opencode_worktree_create`; any unclassified action                                           | hard denial (`unsupported-action`) | refused | refused    | refused |

Internet below Full is refused at once, with an explanation, because the kernel profile has no route
outside the machine; see Q5 and section 6.

## 2. How Keiko runs OpenCode 2.1.4 today

All points are [R] unless tagged.

- **Profile.** `productionOpenCodeToolProfile` returns `native` on macOS and `direct` elsewhere; no
  request field selects it. The audited Linux mount plan still let a shell child read a workspace
  `.env` and a fresh network namespace could not reach the host-loopback gateway, and Windows has no
  native filesystem boundary yet, so both Linux wrappers refuse a native plan
  (`native-linux-backend-unqualified`, [backends][backends]; #3901).
- **Launch.** `buildOpenCodeLaunchProfile` ([profile][profile]) starts
  `opencode serve --hostname 127.0.0.1 --port 0` with a per-run password and a private `HOME`, XDG
  roots and `OPENCODE_DB` under the run's state root. `OPENCODE_CONFIG_DIR` names the run's private
  configuration directory, `OPENCODE_DISABLE_PROJECT_CONFIG=true` switches the repository layer off
  for every profile (#3903; the native profile admits its Markdown-only items as sanitized copies
  in that directory, see Repository items below) and `npm_config_offline=true` keeps the package
  manager offline. The
  native child inherits only `PATH`, locale, `TZ`, `TERM` and `SHELL` from the launcher
  ([backend][backend]); a mapped child inherits `PATH` only to carry the verified ripgrep directory.
- **Native configuration.** `createNativeOpenCodeV2Config` sets `update: "disable"`,
  `share: "disabled"`, `snapshots: true`, one provider `keiko-runtime` with one model alias `coding`
  (text input and output, tool calling on, limits from the admitted gateway geometry, a 30-minute
  provider chunk timeout so a slow reasoning turn is not cut by the runtime while the gateway keeps
  its own deadline), `default_agent: "build"`, native auto-compaction sized from that geometry,
  `tool_output.max_bytes` of 262,144, and exactly one permission rule family: `external_directory`
  is denied except the run's plan directory. No rule names an ordinary action, because the producer
  appends configured rules after each built-in agent's own and the last match wins; every built-in
  agent keeps its own rules (ADR-0137 D10). The server-owned subset (`update`, `share`, `model`,
  `default_agent`, `providers`, `permissions`) is also passed as `OPENCODE_CONFIG_CONTENT`, which the
  producer merges last.
- **Policy hook.** The generated plugin `keiko.native-policy` ([plugin][native-policy-plugin])
  registers the supported `permission.evaluate` hook and asks the server-owned policy for the final
  effect of every evaluated action. It can only keep or narrow the configured effect; a missing,
  failed or oversized answer denies, and so does a resource list over 64 entries of 2,048
  characters. Its shell hook strips the server password and every `KEIKO_*` binding from each shell
  the agent starts; its `execute.before` hook decides the two state-changing Code Mode tools.
  A run is ready only once `GET /api/plugin` reports the three generated plugins
  (`keiko.native-policy`, `keiko.native-context`, `keiko.native-delivery`) active within 10 seconds
  ([readiness][native-readiness]).
- **Repository items (#3903).** Before the first launch the native profile reads the workspace's
  custom agents, commands and skills through the secure read helper, validates each against a
  closed per-kind key allowlist, re-renders its frontmatter and writes the copy into the run's
  private discovery directory (`agents/`, `commands/`, `skills/<name>/SKILL.md`), where the
  producer loads it beside the generated plugins. `model`, permissions, tools, MCP and plugin keys
  never survive; a command template with a shell-substitution block is refused, because the
  producer runs such a block outside the policy hook. `opencode.json`, plugins, nested discovery
  and `.claude/` stay refused. Switch: `KEIKO_CODING_REPOSITORY_ITEMS_ENABLED`; evidence:
  `coding-runtime.repository-items.admitted`
  ([repository-items][repository-items], [sanitizer][repository-items-sanitizer],
  [real-binary proof][repository-items-test]).
- **Delivery tools.** The generated plugin `keiko.native-delivery` registers Keiko's Git delivery
  tools and nothing else with the producer: the mapped profile's own tool source for
  `keiko_git_status`, `keiko_git_diff`, `keiko_git_stage`, `keiko_git_commit`, `keiko_git_push`,
  `keiko_pull_request`, `keiko_git_execute` and `keiko_ci_status`, plus `keiko_verification`, which
  a commit proposal needs for its commit proof ([delivery-tools][delivery-tools]). They reach the
  same tool facade with the same capability, bounds and approvals as a mapped call; the producer
  evaluates no permission for them, so the policy hook adds no second approval.
- **Live authority.** After the policy (and any human decision) allows an effect, the native-effect
  owner revalidates the run's capability, the envelope's action classes and the cumulative
  tool-call budget, one call per native invocation, child sessions included, and a proposed edit
  reserves the size of the producer's diff from the patch budget before it is written
  ([native-effect][native-effect]).
- **Protocol.** 21 operations on 20 paths are admitted and the structural digest is pinned per
  version ([protocol-surface][protocol-surface], [protocol fixture][protocol-fixture]): runtime
  info, session list and create, active session, message history, prompt, interrupt, agent switch
  (`session.switchAgent`), the session diff and the revert operations (`session.diff`,
  `session.revert.stage`, `.commit`, `.clear`), permission list and reply, plugin list, form list,
  reply and cancel, the command list and `session.command`, and the event stream. No fork or share
  operation is admitted; every other operation of the producer has a disposition and an owner in
  section 7. The V2
  client ([v2-client][v2-client]) sends a prompt `text` and `metadata` only; its diff reader drops
  the patch text at the boundary.
- **Network.** The kernel decides, by effective mode: below Full the process tree reaches loopback
  only (the Model Gateway, the tool facade, local dev servers), with unix-socket peers and DNS
  denied; at Full egress is inherited and bounded by the Authority Envelope and the per-action
  policy (`nativeEgress`, [backend][backend]).
- **Filesystem and process boundary.** The `keiko-native` Seatbelt profile
  ([backends][backends], [seatbelt-root][seatbelt-root]) is a read allowlist (the task workspace,
  the run's private state, the runtime payload, system software and toolchain roots derived from the
  launcher's `PATH`), with writes limited to the workspace and the private state. The run's
  configuration directory (policy plugin and settings) is read-only to every descendant. Credential
  stores, credential-named files and Keiko's own state are unreadable, and signals and process
  information reach the tree's own sandbox only. Real-kernel proofs: [runtime-gateway.test.ts][kernel-test].
- **Search.** OpenCode's `glob`, `grep` and file finder run ripgrep. Keiko ships the pinned 15.1.0
  release, verifies its SHA-256 at every launch and puts only that directory in front of the child
  `PATH`, so the runtime never downloads one ([ripgrep-runtime][ripgrep-runtime],
  [ripgrep-launch][ripgrep-launch], [evidence][ripgrep-evidence]). The executable travels in the
  desktop payloads and in the npm runtime packages (`@oscharko-dev/keiko-coding-runtime-<target>`,
  `runtime/native/rg`), so a clean `npm install -g` finds it without an override; a runtime package
  published before it shipped there reports `missing` and search degrades, with the run still
  starting.
- **Context.** Native Build guidance stays intact; the additive `keiko.native-context` hook tells
  the agent that Git delivery belongs to Keiko, names the delivery tools and says that a refusal is a
  policy decision
  ([native context](../../packages/keiko-server/src/coding-runtime/opencodeNativeContext.ts)).
- **Selected private skill (#4025).** A Markdown skill pinned on a Coding conversation is bound to
  the run's task turn when the run begins: the intent is stored as the conversation's user message,
  which takes the selection of that moment as its immutable turn binding. Keiko's coding gateway
  route resolves that binding for every productive dispatch, after the readiness challenge, and
  places the skill's instructions at the start of the request's first user message, so it arrives
  exactly once per request on the native and the mapped profile. The request is then admitted
  again with the skill counted, so the prompt bound and the output allowance include it and an
  overflow is answered as `context_length_exceeded`, which the runtime compacts. A replaced skill
  keeps the run's bound revision; a deleted one refuses the dispatch (`skill-unavailable`). The
  body never leaves Keiko's dispatch path for a log: `coding-sidecar.gateway.skill-attached`
  records the revision, digest and sizes ([gateway][gateway]).
- **Mapped profile (Linux, Windows).** The default direct profile advertises 18 tools: native
  `question` plus 17 `keiko_*` tools ([advertised fixture][tools-fixture]). The Model Gateway
  refuses a request that declares a different tool set (`tool-contract-drift`,
  [gateway][gateway]); on the native profile it forwards the runtime's own bounded advertisement as
  data (at most 128 admissible names, 64 KiB per schema, 512 KiB in all, [native-tools][native-tools]).
  The optional `keiko_research_fetch`, `keiko_skill_discover`, `keiko_skill` and
  `keiko_child_agent` appear only while their prerequisites are ready
  (`deriveOptionalToolAvailability`, [managed-tools][managed-tools]).

**Adding a mapped Keiko capability** takes all of the following together: a descriptor and alias in
the catalog ([catalog][catalog], identity reserved under ADR-0175 D2), a server handler bound to a
facade action, a generated plugin source ([adapter][adapter]), an updated exact tool contract and
digests ([schemas][schemas]), registered activity-log operations (AGENTS.md section 8,
`npm run generate:op-catalog`) and a mode policy mapping (ADR-0138 D2). Runtime-supplied tool
definitions are transport data and cannot register a descriptor, handler, effect or authority
(ADR-0175 D2). The native profile adds nothing per tool: a routine upgrade regenerates the
producer-derived fixture, its compatibility diff names every added or removed tool and permission
action, and the policy must classify each permission action or the hook refuses it.

## 3. Capability matrix

Native tool names are the ones the 2.1.4 producer registers [B] ([native-tools-fixture][native-tools-fixture]):
`read`, `glob`, `grep`, `edit`, `write`, `patch`, `shell`, `webfetch`, `websearch`, `skill`,

The permission check sees the line already split into its commands, so the check is remembered when the policy admits it, with the edit revision and admission observer the governed verifier captures, and only the finished part's whole line (`exitStatusCheck`) can make its exit status (the producer's `metadata.exit`; a non-zero exit is a failed call) the same `verification-summarized` event. A native `edit`, `write` or `patch` is the run's edit, so a run that edited and has no passing check at its current revision continues for verification and then settles `verification-not-evidenced`; a human-refused check blocks it. Real binary: a failing and a passing test run report exit 1 and 0, and `; cd .`, `\|\| cd .` and `\| cat` after a failing test exit zero yet leave the ledger unverified ([qualification][qualification]). Mapped: npm scripts only (`partial`). |

### 3.5 Real-binary qualification of 2026-10-24

Rows T02, T08, T13, T19 and C07 were run against the staged 2.1.4 executable on the working tree of
PR oscharko-dev/Keiko#4064, under the native Seatbelt wrapper with the profile
`buildOpenCodeLaunchProfile` produces, behind a scripted Model Gateway and with Keiko's own
`decideOpenCodeNativePolicy` answering the permission hook ([qualification-test][qualification-test]).
A control that departs from the production launch is named as one in the test. The run is not a
release qualification: it does not drive the real native supervisor, the Model Gateway route or the
Workbench.

- **T02 (`governed`).** A directory is a plain `read` of the path: the result is the immediate
  entries, directories first with a trailing slash, paged by `offset` and `limit` with a
  continuation hint, and the policy is asked for `read` with the path as its resource. No `list` tool
  is advertised. A directory outside the workspace is refused by the configured `external_directory`
  denial before the policy is asked; `.git` and `.env` are refused by the policy as `sensitive-path`.
  The listing of the workspace names its entries (`.env` and files an ignore rule excludes
  included), so a credential file's name reaches the model while its content does not.
- **T08 (`partial`).** The `patch` plugin hooks the runtime's `context`, `compaction` and `generate`
  stages and deletes `patch` from the tools of every model, except that a model id containing `gpt-`
  (and neither `oss` nor `gpt-4`) loses `edit` and `write` instead. The registry holds `patch` under
  `coding`; the advertisement does not. Keiko's gateway admits only the alias `coding`, so no
  reachable model id changes that. Under a `gpt-` alias, which production never uses, `patch`
  added, updated, moved and deleted files in one `edit` ask naming every source and target, with the
  diff size forwarded for the patch budget; a path outside the workspace was refused by the runtime
  with nothing written, `.env` by the policy, and Ask asked.
- **T13 (`partial`).** `shell` accepts `background: true` ("useful for dev servers and long-running
  builds"), returns a shell id and an output file at once, and has no timeout by default. A loopback
  server started this way is a direct child of the runtime and a later foreground `shell` reached it
  in Supervised, which asked for both commands. A turn interrupt (the first step of Keiko's Stop,
  `interruptNativeTree`) cancelled a foreground sleep with no process left; it did not end the
  background job. SIGTERM to the runtime reaped the job; SIGKILL left it as an orphan of launchd, the
  case only the native supervisor's coalition reap covers (`native/runtime-supervisor`, ADR-0137 D5).
  A background job that ended after its turn posted a synthetic message and the runtime started a
  further model turn by itself, while `GET /api/session/active` listed no session during the job, so
  the run's tree status cannot see a pending shell job. Whether Keiko's gateway admits that turn and
  the history shows it is not verified.
- **T19 (`partial`).** The registry holds `todowrite` only under `experimental.todo`. Its permission
  action is `todowrite` with the resource `*`. The native inventory, its fixture and the policy
  recorded it as `todo`, so with the switch on the policy refused the update as an unclassified
  action; they now name `todowrite` (the closed `permission` values of the existing
  `coding-runtime.native-policy.decided` operation changed with it). The V2 history projected the
  completed part as a succeeded tool, not the plan snapshot the safe-activity contract requires; it
  now projects the plan and shows nothing for a part that has not completed.
- **C07 (`gap`).** `Formatter.file` runs after an edit only for formatters registered by the
  `formatter` key; with no key none is registered. The built-in prettier entry needs the project's
  `package.json` to list prettier and then resolves a managed install by the package manager, not the
  project's `node_modules`. With `npm_config_offline=true` it finds none; with the package manager
  online the same run asked a loopback registry for `/prettier`. A configured command formatter
  ran after the edit inside the Seatbelt profile.

## 4. Keiko capabilities without a native counterpart

On both profiles:

- Every native evaluation and decision leaves body-free activity-log evidence
  (`coding-runtime.native-policy.decided`, history projection, `keiko support analyze`).
- The live Authority Envelope, a per-run tool-call budget and the approval lane with a typed,
  content-free request and an authenticated review of the action's own command, paths or address.
- Issue context, Local Project Memory and repository instructions attached as labelled, untrusted
  initial context.
- Model Gateway resilience facts (`model-gateway-retrying`, `recovered`, `retry-stopped`) shown in
  the run status.

Mapped profile only (Linux and Windows; the native profile does not offer them):

- `keiko_ci_status` observes the accepted run's CI readiness (`git.ci-observation`).
- Verification returns a commit-eligibility proof (`commitProof`) separately from the executed
  checks, and delivery runs propose first and redeem later with immutable receipts.
- Edits are bound to whole-file digests, applied as one atomic multi-file transaction and reviewed
  in Ask with the exact diff.
- Research uses request-scoped grants and content quarantine; repository search has a semantic
  rerank; skills come from a server-approved catalog with budget-aware discovery.

  - Math: `$…$`, `\(…\)`, `$$…$$`, `\[…\]` and `math`, `latex`, `tex` and `katex` fences are typeset
    by KaTeX 0.19.0 (MIT), imported on first use as its own chunk, as MathML only, so no KaTeX
    stylesheet or font is added. Options: `trust: false`, `strict: "ignore"`, `maxExpand: 200`,
    `maxSize: 20`, a fresh macro table per formula. A source over 4,000 characters, an empty one, a
    TeX error and an unsupported or unknown command (`\href`, `\url`, `\includegraphics`, `\html*`)
    all show the source as written. KaTeX's markup is parsed into an inert document and every node
    must pass a MathML-only allowlist (no event handler, link or style attribute that loads a URL,
    no `maction` or `annotation-xml`); the checked nodes are the ones inserted, so no
    `dangerouslySetInnerHTML` or `innerHTML` is involved. Prices and shell variables (`$5 and $6`,
    `$HOME`) stay prose; `\$` writes a literal dollar sign.
  - Diffs: `diff` and `patch` fences render through the Changes panel's own `DiffFileSection` with
    its `review` / `rv-*` classes (line classes, sign gutter, +N/−M chips, truncation notices). A diff
    without file or hunk headers (`-old` / `+new` lines alone) gets the same rendering under the
    name "Diff"; a fence that is not a diff, or whose headers carry no hunk, keeps its code view.
  - Streaming: a fence is offered to the renderer only once its closing fence has arrived, and a
    math span only once its closing delimiter has; an open fence keeps the plain streamed code view.
    A finished answer whose last fence was never closed is rendered as complete. Typesetting and
    diff layout are memoized on their own source, so further tokens do not repeat them.
  - Mermaid: not rendered. The fenced source stays, under a "Diagram source" caption that says so.
    Adding Mermaid is blocked by the repository's own supply-chain gates (Q6).
  - Evidence: no new Activity Log operation. Typesetting that falls back on content is an expected
    outcome, not a defect, and is silent by design; a KaTeX chunk that fails to load, or KaTeX
    throwing on a formula, is reported once through `reportClientDiagnostic` (`kind: "other"`, error
    class only, never the formula).

## 7. Service operation inventory (2.1.4)

Acceptance items #3899 (AC3), #3907 (AC2) and #3908 (AC4) ask for the inventory of the original
service, not for an allowlist of the endpoints Keiko already uses. The inventory is producer-derived.
The committed fixture ([inventory-fixture][inventory-fixture]) holds every operation (method, path
and `operationId`) of the `/openapi.json` the pinned 2.1.4 executable serves and every leaf command
of its `--help` tree, captured with a private `HOME` and XDG roots [B]. The tables below are
generated from that fixture and from the disposition tables in [`opencodeServiceInventory.ts`][inventory];
the document test rejects any difference. Sections 3.1 to 3.3 remain the capability view and this
section is the interface view. It grants no authority and changes no runtime behaviour.

Every operation and command has exactly one disposition:

| Disposition       | Meaning                                                                                                                                                                                        |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `admitted`        | In the digest-pinned protocol surface of [`opencodeProtocolSurface.ts`][protocol-surface]. Derived from `OPENCODE_V2_APPROVED_ENDPOINTS`, never listed a second time.                          |
| `covered`         | Not admitted on its own because an admitted operation returns the same facts; nothing is missing.                                                                                              |
| `keiko-operation` | A Keiko product operation provides the capability; the detail names it and its source file.                                                                                                    |
| `refused`         | Not offered. The reason is one of the closed values below and the owner is the epic #3897 issue that owns the decision or the work. A refusal is neither parity evidence nor a permanent veto. |

The refusal reasons:

| Reason                         | Meaning                                                                                                                                                                                                                              |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `not-yet-implemented`          | A customer-visible standalone capability Keiko intends to offer; the owner issue carries the implementation and the matrix row carries the status.                                                                                   |
| `leaves-machine`               | Needs outbound internet or another server, which a firewalled customer does not have (ADR-0137 D10).                                                                                                                                 |
| `keiko-owns-workspace-binding` | Names, creates or moves the project, worktree or session location. Keiko binds the task workspace ([ADR-0088][adr-0088], [ADR-0089][adr-0089]).                                                                                      |
| `keiko-owns-authority`         | Would create a permission, an environment or an unconfined write outside the policy hook and the Authority Envelope ([ADR-0129][adr-0129]).                                                                                          |
| `keiko-owns-configuration`     | Reads or changes server-owned configuration or the model selection (ADR-0163 D6).                                                                                                                                                    |
| `keiko-owns-credentials`       | Stores, lists or negotiates provider credentials, which never reach the runtime (ADR-0163 D6).                                                                                                                                       |
| `experimental-unadmitted`      | The producer marks the operation experimental (`/api/experimental/`). No experimental operation is admitted without a qualifying producer contract test (#3908).                                                                     |
| `host-surface`                 | Serves another client or host: pairing, terminals, debugging, plugin RPC and additional client protocols. Keiko is the only client and owns the UI; these stay open acceptance items of their owner (pairing and statistics: #3899). |

What keeps the inventory true:

- The unit test ([inventory-test][inventory-test]) fails when an operation or command of the fixture
  has no disposition, when a disposition names an operation the fixture does not contain, when an
  operation is listed twice or is both admitted and listed, and when the `admitted` set differs
  from the digest-pinned protocol surface (`OPENCODE_V2_APPROVED_ENDPOINTS` and the projection of its
  fixture). Keiko-operation sources must exist, owners must be epic issues and matrix rows must
  exist in this document.
- The opt-in real-binary test ([inventory-real-test][inventory-real-test]) starts the pinned
  executable, reads its live `/openapi.json` and walks its `--help` tree. Any operation or command
  added, removed or moved against the fixture fails it; that is the automated drift detection of an
  upgrade. It runs with `KEIKO_OPENCODE_REAL_BINARY` and `KEIKO_OPENCODE_REAL_RESOURCE_ROOT` set.
- An upgrade regenerates the fixture from the new executable (the real-binary test rewrites it with
  `KEIKO_WRITE_OPENCODE_SERVICE_INVENTORY_FIXTURE=1`; format it with prettier).
  `diffOpenCodeServiceOperations` then names the added, removed and moved operations and marks a
  removal or a move as breaking, and the unit test names every added operation or command that has
  no disposition. Nothing becomes admitted by default: only the digest-pinned endpoint list admits.
- After a change to a table, regenerate this section with
  `KEIKO_WRITE_OPENCODE_SERVICE_INVENTORY_DOC=1 npx vitest run packages/keiko-server/src/coding-runtime/opencodeServiceInventory.test.ts`
  and `npx prettier --write docs/qa/opencode-capability-parity.md`.

```sh
OC=.portable-sidecar-payloads/<target>/opencode-compatible/payload/bin/opencode
"$OC" --version                      # opencode v2.1.4
"$OC" --help                         # subcommands and flags (the recursive walk is the section 7 CLI inventory)
"$OC" mcp --help                     # likewise: plugin, session, debug, run, serve
grep -a -o -E 'id:"opencode\.[A-Za-z0-9._-]+"' "$OC" | sort -u   # native plugin ids
```

The plugin ids list the tool plugins (`opencode.tool.*`: edit, glob, grep, patch, question, read,
shell, skill, subagent, todo (which registers the tool `todowrite`), webfetch, websearch, write; no `lsp`), the configuration plugins
(`opencode.config.*`) and the web search providers. The tool inventory itself is the
producer-derived capture of `ctx.tool.list()` in
[native-tools-fixture][native-tools-fixture], regenerated on every runtime upgrade. The bundle is
plain text inside the executable, so a fixed-string `grep -a -b -o -F` finds a byte offset and `dd`
reads its context. Offsets and minified names change with every build; the plugin ids and tool
names are the stable facts. The opt-in real-binary suites run with `KEIKO_OPENCODE_REAL_BINARY` and
`KEIKO_OPENCODE_REAL_RESOURCE_ROOT` set, the ripgrep suite additionally after
`npm run provision:ripgrep`.
