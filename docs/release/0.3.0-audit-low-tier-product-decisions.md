# 0.3.0 Audit Low/Hardening/Optimization Product Decisions (#2907)

Status: accepted product-owner dispositions recorded on 2026-08-28. This record changes no product
code. Each target-state decision below is tracked for implementation and verification in its linked
follow-up issue; until the linked implementation merges and verification completes, the current code
and its fail-closed behavior remain authoritative.

Every finding was re-verified against the current `dev` head (branch `oscharko/issue-2907-b8ea02`,
HEAD `4419d38a` at investigation time) before disposition, not taken on trust from the audit's
recorded excerpts — anchors decay as remediation lands elsewhere, and several findings in this
cluster had already drifted: 4 were superseded outright by unrelated prior work (KEIKO-0621,
KEIKO-0683, KEIKO-0699, KEIKO-1035), and one (KEIKO-0618) turned out to describe an edge that is
still load-bearing elsewhere in the codebase, where the audit's own reachability analysis was correct
for one call site but incomplete for the shared contract as a whole.

## Decision rules

- Working, clean, secure, verified code is authoritative. ADRs are guardrails and must describe the
  implementation that actually ships.
- No gate, trust boundary, evidence redaction rule, or regression pin is weakened to close an audit
  item.
- Existing subsystems are extended at their owning layer. Parallel policy, evidence, citation,
  authority, or persistence mechanisms are not introduced.
- Dead code proven to have zero production callers is deleted, per AGENTS.md §6, rather than left as
  scaffolding or documented-and-kept by default.
- A regression pin may be strengthened or relocated, never relaxed (AGENTS.md §7); where this cluster
  touches an existing pin (KEIKO-0873), the fix strengthens it.
- Every moved item remains open in its implementation issue; this record is not evidence that its
  target behavior already ships.

The source backlog classifies no item in this cluster as `adr-obsolete`; no superseding ADR is
required by this decision cluster. Two items are `code-deviates` (KEIKO-0631, an inert method the
code should simply stop advertising; KEIKO-0792 and KEIKO-0796, coverage/consistency gaps in an
otherwise-correct implementation) and one is `doc-is-stale` (KEIKO-0549, governed by a superseded
ADR). Twelve items carried `authoritySide: undetermined` in the source backlog; eight of those were
genuine product-owner calls requiring explicit confirmation and are marked "owner decision" below,
resolved on 2026-08-28. The remaining four `undetermined` items resolved cleanly under ordinary
security/engineering analysis without needing a product-owner call (KEIKO-0671, resolved by an
already-in-force ADR; KEIKO-0744 and KEIKO-0969, resolved by tracing the actual security/lifecycle
model; KEIKO-0652, resolved by tracing the real call graph) and are marked accordingly.

## ADR and release impact

This cluster contains decisions only and is `internal-only`; it changes no user-visible behavior,
runtime contract, package version, or state. No superseding ADR is required by this decision cluster.
Two follow-ups touch ADR text directly as part of their scope: KEIKO-0846 (flip ADR-0052..ADR-0057
Status to Accepted, [#3330](https://github.com/oscharko-dev/Keiko/issues/3330)) and KEIKO-0666
(narrow ADR-0105's reuse claim to the leaf contract,
[#3319](https://github.com/oscharko-dev/Keiko/issues/3319)); KEIKO-0618's follow-up corrects a
misleading code comment about FSM-edge reachability without touching any ADR
([#3312](https://github.com/oscharko-dev/Keiko/issues/3312)).

Eight table rows carry the "owner decision" marker, each resolved by explicit product-owner
confirmation on 2026-08-28: extend harness-loop compaction into the hard-fail gate (KEIKO-0726),
document CODEOWNERS' single-maintainer intent (KEIKO-0786), cross-validate voice `durationMs`
against decoded audio size (KEIKO-0844), keep the installed-artifact smoke-test gap opportunistic
(KEIKO-0913), flip ADR-0052..ADR-0057 to Accepted (KEIKO-0846), narrow `EditorM7CommandScope`
(KEIKO-0875), build the debug-lifecycle `(eventKind, state)` legality table (KEIKO-0890), and add
per-instance mutex serialization to workspace reconciliation (KEIKO-0996). Four further items carried
`authoritySide: undetermined` in the source backlog but resolved cleanly without a product-owner
call: KEIKO-0671 (already answered by ADR-0163 D6, in force), KEIKO-0744 and KEIKO-0969 (resolved by
tracing the actual cryptographic-verification and OS-lifecycle models respectively), and KEIKO-0652
(resolved by tracing the real call graph — no live exploit exists, closing the mitigation at the
owning layer is ordinary defense-in-depth).

Six items are accepted as-is (`wontfix`) with no follow-up issue: KEIKO-0612, KEIKO-0672 (both
designed, documented, non-blocking evidence-staleness behavior), KEIKO-0744, KEIKO-0969 (both
resolve via the actual security/lifecycle model rather than a real gap), KEIKO-0896 (a confirmed
deliberate fail-closed stub), and KEIKO-0913 (owner-confirmed opportunistic policy). Four items are
superseded by unrelated prior work with no further action: KEIKO-0621 (#2945/PR #3300), KEIKO-0699
(commit `fa6cd04f`), KEIKO-1035 (commit `dd51fe58`), and KEIKO-0683 (KEIKO-0520's config-parse
guard).
