Status: accepted product-owner dispositions recorded on 2026-08-13. This record changes no product
code. Each target-state decision below is tracked for implementation and verification in its linked
follow-up issue; until the linked implementation merges and verification completes, the current
code and its fail-closed behavior remain authoritative.

Every finding was re-verified against the current `dev` head (`a5f5511b`) before disposition: 42 of
the 44 findings hold unchanged, one changed immaterially (KEIKO-0182 gained a single incidental

(KEIKO-0444, deleted by `bc78716b` / #3067).

## Decision rules

- Working, clean, secure, verified code is authoritative. ADRs are guardrails and must describe the
  implementation that actually ships.
- No gate, trust boundary, evidence redaction rule, or regression pin is weakened to close an audit
  item.
- Existing subsystems are extended at their owning layer. Parallel policy, evidence, citation,
  authority, or persistence mechanisms are not introduced.
- An affected existing ADR is corrected atomically with the corresponding working implementation.
  This decision cluster does not create superseding ADRs merely to repair stale text.
- Investigation findings require a failure-first production-shaped fixture before a behavioral fix.
- Every moved item remains open in its implementation issue; this record is not evidence that its
  target behavior already ships.

The source backlog classifies no item in this cluster as `adr-obsolete`. KEIKO-0219 is the sole
`code-deviates` finding (ADR-0104 still expresses intent; the hook drifted), so its code is
corrected in its follow-up. The three `doc-is-stale` findings (KEIKO-0138, KEIKO-0141, KEIKO-0148)
update documentation to match verified shipped behavior. The ten formerly `undetermined` items were
resolved by explicit product-owner decision on 2026-08-13 and are marked below.

## ADR and release impact

This cluster contains decisions only and is `internal-only`; it changes no user-visible behavior,
runtime contract, package version, or state. Adding target-state prose to an ADR before its code
exists would make the ADR contradict the product. Each follow-up therefore names the existing ADR
sections it must update in the same pull request as the tested implementation (ADR-0104 in #3107,
ADR-0107/ADR-0108 in #3105, ADR-0053 in #3123).

Fourteen table rows carry the "owner decision" marker. Ten of them are the formerly `undetermined`
findings, each resolved explicitly by the product owner on 2026-08-13: wire the governed ports
(KEIKO-0156), keep and harden voice recap (KEIKO-0343), build out the Twin surface (KEIKO-0233,
KEIKO-0363), harmonize Jira onto the ADR-0128 connector (KEIKO-0201), legalize archived-forget
(KEIKO-0187, KEIKO-0466), implement the eviction vocabulary (KEIKO-0153), accept the all-grant
mode policies as intended (KEIKO-0250), and reconcile ADR-0053 without a code revert (KEIKO-0390).
The other four marked rows are companions resolved under the same explicit owner confirmations of
2026-08-13: KEIKO-0441 inside the voice-recap decision, KEIKO-0350 inside the Jira harmonization,
KEIKO-0293 inside the Twin build-out direction, and KEIKO-0298 (wire the supervised task grants)
under the owner's blanket confirmation of the recommended dispositions in the same session.

The Twin build-out (#3108) is deliberately sequenced with the already-accepted #2950 mock deletion:
the prototype state model is removed, and the genuine server-truth replacement ships under #3108 —
extending the prototype was rejected on both integrity and reuse-first grounds.
