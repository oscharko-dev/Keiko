# Voice Digital Twin architecture (Epic #491)

This directory holds the architecture baseline, current canonical Voice contracts, privacy contract,
deployment matrix, supply-chain policy, historical closure evidence, and implementation sequencing for
Keiko's optional, capability-gated **Voice Digital Twin**. It originated as the documentation deliverable of
Issue [#492](https://github.com/oscharko-dev/Keiko/issues/492); the product implementation now exists and is
governed by the later ADR amendments identified below.

The architecture baseline is
[ADR-0100](../adr/ADR-0100-voice-digital-twin-capability-architecture.md), amended by ADR-0102 and the current
canonical authority [ADR-0154](../adr/ADR-0154-canonical-twin-voice-pipeline.md). The documents in this
directory expand those decisions into detailed contracts. Historical Epic #491 closure is
recorded by Issue [#506](https://github.com/oscharko-dev/Keiko/issues/506) in
[production-readiness.md](production-readiness.md) and
[ADR-0111](../adr/ADR-0111-voice-production-readiness-gate.md) (documentation only). The epic-level
coordination closure ledger is recorded in [epic-491-closure.md](epic-491-closure.md).

## Core invariants (summary)

1. Voice is **optional and capability-gated**. Keiko starts and remains fully usable when no voice model is
   configured, unreachable, disabled by policy, or unsupported by the provider.
2. **STT-only dictation** is distinct from Twin Voice. Twin Voice requires input-only Realtime WebRTC with
   explicit final transcription plus an independent speech-output provider and persona mapping.
3. **WebSocket** is the loopback control/signaling plane; native browser **WebRTC** carries a send-only
   microphone track. Realtime owns no assistant response, tool, memory, grounding, or output-audio path.
4. Provider HTTP calls use configured Model Gateway endpoints. The separately reviewed WebRTC media plane
   follows provider SDP, supplies no custom STUN/TURN configuration, and requires deployment-network
   acceptance. Raw audio and partial transcripts remain ephemeral; the settled final transcript is persisted
   through canonical chat.
5. **No new runtime media packages by default** beyond the existing `ws` dependency and browser-native WebRTC
   APIs.

These invariants are derived from Epic #491 and grounded in the existing Keiko seams cited in
[ADR-0100](../adr/ADR-0100-voice-digital-twin-capability-architecture.md).
